# Project context

## Outcome and constraints

`brief.md` describes a roughly 75-second mysterious, hand-painted Unsloth Studio promo. Its target is 1920x1080, 24 fps, stereo 48 kHz and `render/final.mp4`. The owner also wants a reusable pipeline. Preserve the brief unless the owner approves a substitution.

All coding and media-model inference runs on this machine. Internet is allowed for acquisition, setup and research. Strata is one optional coding setup and may be stopped when GPU memory is needed. Prefer one loaded GPU model at a time; check actual residency, jobs and free memory before switching. CPU/offload is acceptable if the chosen local tool supports it and the outcome is measured.

This is a personal, non-commercial film. Check the actual license and usage terms of every selected model before production; the old model list and its unverified claims are not a license decision. Do not clone a real person's voice without appropriate consent.

## Evidence and safety

On-screen statements about Unsloth's features, names, numbers, timings and training results must be supported by real MCP call logs and their raw outputs. Do not fabricate evidence or modify source logs. The existing OMP hook was previously tested for standard OMP CLI, but another client must prove its own capture path before its calls are treated as evidence. Keep factual claims out of a pilot if they cannot be supported. Caption or narration text should match the actual approved script and spoken content.

Never print, write, request or commit an API key. Use local configuration that reads the existing user-scoped `UNSLOTH_API_KEY` without displaying it. Preserve real outputs and distinguish verified measurements from estimates or prior reports.

## Handoffs and review

`STATUS.md` is the outcome-level state. `handoff.md` is the live resume point: owner, stage, completed and pending work, evidence, failures, active jobs, and exact next action. Update both before a GPU switch or session exit. Use project-relative artifact paths where practical and absolute forward-slash Windows paths where Studio requires them.

The owner reviews the pilot and final film. A creative substitution for a requested feature requires their decision. Ordinary local implementation, testing, downloads and reversible resource switching within the authorized task can proceed without repeated approval.
